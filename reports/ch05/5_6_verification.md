## 环境和张量

- Python 3.8.20，PyTorch 2.4.1+cu121，CUDA 构建版本 12.1。CPU 为 Intel Core i7-14650HX。RTX 4060 Laptop GPU 可见 1 张，驱动 566.24，nvidia-smi 显存 8188 MiB。
- `try_gpu(0)` 为 `cuda:0`，`try_gpu(1)` 为 `cpu`。直接相加 CPU 与 CUDA 非标量张量触发预期错误。迁移后相加在 CUDA 上得到 `[[1,2,3],[4,5,6]]`。同设备再次调用 `to` 返回同一个张量。
- `--device cpu` 走强制 CPU 路径。另以 `CUDA_VISIBLE_DEVICES=-1` 隐藏 GPU，默认命令自动回退 CPU，检查设备列表、训练、恢复、CPU 计时和跳过双卡均通过。

矩阵结果通过容差检查，CPU 与 GPU 最大元素绝对差分别为 9.54e-7 和 4.58e-4。绝对差随输出尺度和累积长度变化，代码按元素同时使用绝对及相对容差。CPU 一次实验的数据反映指定线程数和当前负载。

1000 次 100×100 乘法及 Frobenius 范数，逐次 `.item()` 为 99.6779 ms，设备向量一次读出为 87.1932 ms，全部范数逐项一致。第一个范数 998.28540039，CPU 用 float64 从相同输入重新计算平方和开方为 998.28540076。双 GPU 分支因可见设备数量不足跳过。双卡方案的串行与并行各计算两个乘积，同步参与计时的设备，输入传输在计时之外。
